title: 12.16.9.1 Spatial Relation Functions That Use Object Shapes
---

The OpenGIS specification defines the following functions to test the relationship between two geometry values g1 and g2, using precise object shapes. The return values 1 and 0 indicate true and false, respectively, except for [ST\\_Distance\(\)](#page-157-5) and [Distance\(\)](#page-157-1), which return distance values.

These functions support all argument type combinations except those that are inapplicable according to the Open Geospatial Consortium specification.

<span id="page-157-0"></span>• [Crosses\(](#page-157-0)g1, g2)

```
ST_Crosses() and Crosses() are synonyms. For more information, see the description of
ST_Crosses().
```

[Crosses\(\)](#page-157-0) is deprecated; expect it to be removed in a future MySQL release. Use [ST\\_Crosses\(\)](#page-157-3) instead.

<span id="page-157-1"></span>• [Distance\(](#page-157-1)g1, g2)

[ST\\_Distance\(\)](#page-157-5) and [Distance\(\)](#page-157-1) are synonyms. For more information, see the description of [ST\\_Distance\(\)](#page-157-5).

[Distance\(\)](#page-157-1) is deprecated; expect it to be removed in a future MySQL release. Use [ST\\_Distance\(\)](#page-157-5) instead.

<span id="page-157-2"></span>• [ST\\_Contains\(](#page-157-2)g1, g2)

Returns 1 or 0 to indicate whether g1 completely contains g2. This tests the opposite relationship as [ST\\_Within\(\)](#page-158-4).

<span id="page-157-3"></span>• [ST\\_Crosses\(](#page-157-3)g1, g2)

The term spatially crosses denotes a spatial relation between two given geometries that has the following properties:

- The two geometries intersect.
- Their intersection results in a geometry that has a dimension that is one less than the maximum dimension of the two given geometries.
- Their intersection is not equal to either of the two given geometries.

This function returns 1 or 0 to indicate whether g1 spatially crosses g2. If g1 is a Polygon or a MultiPolygon, or if g2 is a Point or a MultiPoint, the return value is NULL.

This function returns 0 if called with an inapplicable geometry argument type combination. For example, it returns 0 if the first argument is a Polygon or MultiPolygon and/or the second argument is a Point or MultiPoint.

Returns 1 if g1 spatially crosses g2. Returns NULL if g1 is a Polygon or a MultiPolygon, or if g2 is a Point or a MultiPoint. Otherwise, returns 0.

This function returns 0 if called with an inapplicable geometry argument type combination. For example, it returns 0 if the first argument is a Polygon or MultiPolygon and/or the second argument is a Point or MultiPoint.

```
ST_Crosses() and Crosses() are synonyms.
```

<span id="page-157-4"></span>• [ST\\_Disjoint\(](#page-157-4)g1, g2)

Returns 1 or 0 to indicate whether g1 is spatially disjoint from (does not intersect) g2.

<span id="page-157-5"></span>• [ST\\_Distance\(](#page-157-5)g1, g2)

Returns the distance between g1 and g2. If either argument is NULL or an empty geometry, the return value is NULL.

This function processes geometry collections by returning the shortest distance among all combinations of the components of the two geometry arguments.

If an intermediate or final result produces NaN or a negative number, an [ER\\_GIS\\_INVALID\\_DATA](https://dev.mysql.com/doc/mysql-errors/5.7/en/server-error-reference.md#error_er_gis_invalid_data) error occurs.

```
mysql> SET @g1 = Point(1,1);
mysql> SET @g2 = Point(2,2);
mysql> SELECT ST_Distance(@g1, @g2);
+-----------------------+
| ST_Distance(@g1, @g2) |
+-----------------------+
| 1.4142135623730951 |
+-----------------------+
```

[ST\\_Distance\(\)](#page-157-5) and [Distance\(\)](#page-157-1) are synonyms.

<span id="page-158-0"></span>• [ST\\_Equals\(](#page-158-0)g1, g2)

Returns 1 or 0 to indicate whether g1 is spatially equal to g2.

```
mysql> SET @g1 = Point(1,1), @g2 = Point(2,2);
mysql> SELECT ST_Equals(@g1, @g1), ST_Equals(@g1, @g2);
+---------------------+---------------------+
| ST_Equals(@g1, @g1) | ST_Equals(@g1, @g2) |
+---------------------+---------------------+
| 1 | 0 |
+---------------------+---------------------+
```

<span id="page-158-1"></span>• [ST\\_Intersects\(](#page-158-1)g1, g2)

Returns 1 or 0 to indicate whether g1 spatially intersects g2.

<span id="page-158-2"></span>• [ST\\_Overlaps\(](#page-158-2)g1, g2)

Two geometries spatially overlap if they intersect and their intersection results in a geometry of the same dimension but not equal to either of the given geometries.

This function returns 1 or 0 to indicate whether g1 spatially overlaps g2.

This function returns 0 if called with an inapplicable geometry argument type combination. For example, it returns 0 if called with geometries of different dimensions or any argument is a Point.

<span id="page-158-3"></span>• [ST\\_Touches\(](#page-158-3)g1, g2)

Two geometries spatially touch if their interiors do not intersect, but the boundary of one of the geometries intersects either the boundary or the interior of the other.

This function returns 1 or 0 to indicate whether g1 spatially touches g2.

This function returns 0 if called with an inapplicable geometry argument type combination. For example, it returns 0 if either of the arguments is a Point or MultiPoint.

[ST\\_Touches\(\)](#page-158-3) and [Touches\(\)](#page-158-5) are synonyms.

<span id="page-158-4"></span>• [ST\\_Within\(](#page-158-4)g1, g2)

Returns 1 or 0 to indicate whether g1 is spatially within g2. This tests the opposite relationship as [ST\\_Contains\(\)](#page-157-2).

<span id="page-158-5"></span>• [Touches\(](#page-158-5)g1, g2)

[ST\\_Touches\(\)](#page-158-3) and [Touches\(\)](#page-158-5) are synonyms. For more information, see the description of [ST\\_Touches\(\)](#page-158-3).

[Touches\(\)](#page-158-5) is deprecated; expect it to be removed in a future MySQL release. Use [ST\\_Touches\(\)](#page-158-3) instead.
