---

```
DECLARE cursor_name CURSOR FOR select_statement
```

This statement declares a cursor and associates it with a SELECT statement that retrieves the rows to be traversed by the cursor. To fetch the rows later, use a [FETCH](#page-61-0) statement. The number of columns retrieved by the SELECT statement must match the number of output variables specified in the [FETCH](#page-61-0) statement.

The SELECT statement cannot have an INTO clause.

Cursor declarations must appear before handler declarations and after variable and condition declarations.

A stored program may contain multiple cursor declarations, but each cursor declared in a given block must have a unique name. For an example, see [Section 13.6.6, "Cursors".](#page-59-1)

For information available through [SHOW](#page-134-0) statements, it is possible in many cases to obtain equivalent information by using a cursor with an INFORMATION\_SCHEMA table.

# <span id="page-61-0"></span>**13.6.6.3 Cursor FETCH Statement**

```
FETCH [[NEXT] FROM] cursor_name INTO var_name [, var_name] ...
```

This statement fetches the next row for the SELECT statement associated with the specified cursor (which must be open), and advances the cursor pointer. If a row exists, the fetched columns are stored in the named variables. The number of columns retrieved by the SELECT statement must match the number of output variables specified in the [FETCH](#page-61-0) statement.

If no more rows are available, a No Data condition occurs with SQLSTATE value '02000'. To detect this condition, you can set up a handler for it (or for a NOT FOUND condition). For an example, see [Section 13.6.6, "Cursors"](#page-59-1).

Be aware that another operation, such as a SELECT or another FETCH, may also cause the handler to execute by raising the same condition. If it is necessary to distinguish which operation raised the condition, place the operation within its own [BEGIN ... END](#page-52-0) block so that it can be associated with its own handler.
