source: PostgreSQL 16 Reference
title: 46.7. Explicit Subtransactions
---

Recovering from errors caused by database access as described in [Section 46.6.2](#page-52-0) can lead to an undesirable situation where some operations succeed before one of them fails, and after recovering from that error the data is left in an inconsistent state. PL/Python offers a solution to this problem in the form of explicit subtransactions.
