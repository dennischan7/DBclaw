# 性能调优工作流 (Optimization)

> 适用意图: `optimize` — 索引优化、查询调优、执行计划分析
> 风险等级: L0 (分析阶段) / L2 (CREATE INDEX) / L3 (DROP INDEX)
> 审批要求: 分析无需审批，操作执行按风险等级审批

## 执行流程

```
用户输入 (慢查询/调优需求)
  │
  ▼
┌─────────────────────┐
│ 1. 意图分类          │ → 确认为调优操作
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│ 2. 知识库检索        │ → library_search("index optimization", db_type)
│    - 索引最佳实践    │    获取方言特定的优化建议
│    - 优化器特性      │
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│ 3. 元数据分析        │ → metadata_read(table, instance)
│    - 表结构          │    获取列类型、数据分布
│    - 现有索引        │    避免重复索引
│    - 表大小/行数     │
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│ 4. 执行计划分析      │ → explain_analyze(sql, instance)
│    - 全表扫描        │    识别优化点
│    - 索引使用情况    │    判断索引是否被利用
│    - 连接算法        │    Nested Loop vs Hash Join
│    - 排序开销        │
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│ 5. 生成优化建议      │ → 基于分析结果生成:
│    - 索引建议        │    CREATE INDEX 语句
│    - 查询重写建议    │    等价但更优的SQL
│    - 配置调整建议    │    数据库参数优化
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│ 6. 用户确认执行      │ → 如果涉及DDL操作
│    (可选)            │    转入DDL变更工作流
└─────────────────────┘
```

## 自动识别的优化信号

| 信号 | 建议动作 |
|------|---------|
| 全表扫描 (Seq Scan) | 建议创建索引 |
| 缺失索引 (Index Scan possible) | 建议创建覆盖索引 |
| 排序使用临时表 | 建议调整 sort_buffer 或添加索引 |
| Nested Loop + 大表 | 建议改用 Hash Join 或添加索引 |
| 预估行数 >> 实际行数 | 建议更新统计信息 (ANALYZE TABLE) |
